# E1 canonical evidence access checklist v1

Status: prepared on baseline `a52a6b4cc140ada3312170f068cf940bcbead8b5`; no canonical database or export was available in this worktree. Give the operator this checklist through an approved channel. Do not paste connection strings, tokens, private keys, customer payloads, or unredacted receipts into an issue or chat.

## Minimum operator package

1. **Source and immutability.** Identify the canonical deployment and database, UTC capture time, migration versions (especially `20261007_011` and `20261007_013`), snapshot/backup identifier, and SHA-256 of the exact backup or export bytes. Supply a restored, access-controlled copy that cannot receive application writes, or an equivalent immutable export. Record backup tool, format (for example PostgreSQL custom archive or SQL), PostgreSQL version, restore procedure, and parity checks. The repository does not establish which backup format the operator actually uses. A repeatable-read transaction against a changing production database is consistent for one audit run but is not an immutable, repeatable dataset.
2. **Read-only access.** Create a dedicated account with `SELECT` on `observation_receipts`, `judgment_receipts`, `judgment_observations`, `execution_receipts`, and `evaluation_receipts`, and no `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`, table ownership, superuser, trigger-disabling, or schema-altering privileges. Put its connection string in the operator secret store as `DECISIONS_HISTORY_READONLY_DATABASE_URL`; do not commit or transmit the value. Prefer the isolated restored copy over a production connection. Confirm row-level policies and schema name, if applicable. The existing auditor checks read-only transaction state and write privileges on the four receipt tables; an operator must additionally verify the link table and higher database privileges.
3. **Issuer trust.** Supply the historical `JUDGMENT_ISSUER` identifier and an independently authenticated, versioned public Ed25519 SPKI key registry with `key_id`, `valid_from`, `valid_until`, and revocation state at issuance and review time. Record the registry hash and its custodian. The auditor accepts a JSON file of `{ "issuer": "...", "keys": [...] }` via `--issuer-trust`. Never provide `JUDGMENT_SIGNING_PRIVATE_KEY`, payment keys, admin tokens, or a key copied solely from the receipt being assessed. Unsigned historical judgments remain unsigned; do not re-sign them.
4. **Execution proof archive.** For every candidate X, retain the original signed `/v1/execute-proof` submission, its exact canonical bytes/hash, signer identity, provider request/response artifacts, and the settlement transaction/log/block evidence needed to recheck the supported profile. The stored X submission hash alone cannot reconstruct the signature. For `base_usdc_external.v1`, record chain ID 8453, known USDC contract, payer, recipient, atomic amount, transaction and block hashes, finality height, block time, and RPC source. A finalized transfer proves settlement, not service success.
5. **Outcome archive and reviewer authority.** Preserve the actual delivered service result, provider request ID, response body/headers or provider-signed artifact, capture time, rubric frozen before execution, evaluator identity and authority, and independent outcome-review record. Provide de-identified, content-addressed artifact references accessible to reviewers. An internal Evaluation `evidence_refs` value or `verified: true` assertion is not independent outcome proof.
6. **Coverage and privacy.** Record export table counts and high-water marks, cursor/range coverage, omitted partitions, retention gaps, unavailable artifacts, data-use permission, redaction method, and redaction-map custodian. Never turn a missing artifact into a synthetic parent. Preserve raw evidence in the approved restricted store; publish only hashes, classifications, aggregate counts, and redacted case facts.

## Read-only audit sequence after access is approved

1. Verify the backup/export digest and restored schema against the operator record. Record the exact Git commit and public trust-registry digest. Keep the restored copy offline from application writers.
2. Run `npm run audit:decisions-history -- --output <new-private-path> --schema <schema> --issuer-trust <public-trust-file>` with the dedicated read-only URL supplied by the secret store. The output path must be new: the auditor opens it exclusively with mode `0600`. Do not attach raw receipts to the public report.
3. Reconcile each source count with the export manifest. The auditor has a default 10,000-row cap per receipt table and aborts if exceeded; raise `--max-rows` only within its 100,000 limit or extend pagination under review. A capped or partial audit does not establish inventory completeness.
4. Examine rejected hashes/schemas, duplicate IDs, orphan Evaluations, synthetic sources, unverified issuer authority, missing Evaluation parents, and invalid O→J→X→E pointers. Verify time order and scope. Keep missing, invalid, pending, and unverifiable categories distinct; unknown counts remain `null`, never zero.
5. Separately reverify original signed execution submissions and settlement against independent rail evidence, then independently inspect outcome artifacts and reviewer authority. The current audit CLI deliberately supplies neither external verifier callback, so its output cannot alone classify any X as `verified_complete`.
6. Freeze a new versioned inventory with source digest, public trust digest, audit output digest, reviewer records, verification method and code commit. Require an independent reviewer to sign off before reporting any verified-complete count.

No database access, migration, payment, service call, or production write is authorized by this checklist.
