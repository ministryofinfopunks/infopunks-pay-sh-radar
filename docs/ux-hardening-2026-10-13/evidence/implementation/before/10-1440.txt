DEVELOPER SURFACE

Before your agent pays, it checks Infopunks.

Infopunks is the pre-spend intelligence layer before payment. It returns receipt-backed route intelligence, known blockers, safer alternatives, and validation context before economic action.

Infopunks is not executing payment. The SDK calls POST /v1/pre-spend/check against https://radar.infopunks.fun.

SDK USAGE

USE THE PRE-SPEND CLIENT

One call returns a verified Judgment. Tenant credentials bind agent identity; wallet signing requires a bounded policy and an explicit approval callback. Judgment never executes the proposed spend.

import { createInfopunksClient, createX402WalletPayment } from "infopunks-pay-sh-radar/sdk";

const client = createInfopunksClient({
  baseUrl: "https://radar.infopunks.fun",
  apiKey: process.env.INFOPUNKS_TENANT_KEY!,
  payment: createX402WalletPayment({
    signer: walletSigner,
    policy: { network: "eip155:8453", asset: "USDC", payTo: operatorPayTo, maxAmountAtomic: "25000000" },
    approve: async ({ judgment }) => confirm(`Pay ${judgment.cost.amount} ${judgment.cost.asset} for this Judgment?`)
  })
});

const result = await client.judge({
  intent: "buy_market_research",
  subject: "service:market_research",
  budget: 25,
  risk: "low",
  requiredConfidence: 80
});

// Returns only after the canonical receipt is verified. This never executes the spend.
console.log(result.state, result.canonical_judgment);

API

POST /V1/PRE-SPEND/CHECK

Canonical decisions: proceed, test_spend_first, do_not_spend, insufficient_evidence. Inspect canonical_judgment; legacy diagnostic verdicts cannot authorize spend. Subject network is independent of fee settlement. The strict radar-judgment-context.v1 extension binds a namespaced subject, policy version, accepted evidence references, fee settlement network and expiry. RH market policy remains read-only and unqualified for trading. Native Solana fee settlement is unavailable. Canonical proof reads require operator authentication.

Builders can call the HTTP endpoint directly when they do not want the SDK wrapper. The public contract is the intelligence layer before payment, not the payment client itself.

DECISION STATES

CRISP OUTCOMES FOR BUILDERS
proceed
Policy-bound assessment. A valid canonical receipt and separate execution authorization are required before action.
test_spend_first
Only a policy-defined bounded test is justified. Execution remains separately authorized.
do_not_spend
Reviewed evidence establishes a deterministic blocker.
insufficient_evidence
Abstain for free. Missing, stale, or unqualified evidence cannot authorize action.
