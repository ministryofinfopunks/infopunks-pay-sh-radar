## What already works

- The homepage shows “NO CHECK RUN,” “AWAITING EVIDENCE,” and no issued receipt. Signal Lens, terminal framing and cyan/policy colors are retained.
- The selected route transfers into Spend Terminal through the subject deep link.
- A real local insufficient-evidence response stays free, with no canonical receipt, execution authorization or verified outcome.
- Pending Execution remains pending. Evaluation record existence does not fill missing earlier stages.
- Changing tenant identity removes the previously loaded private record. Cross-tenant inspection produces the generic unavailable response without exposing another tenant's evidence.
- Mobile navigation closes with Escape and restores trigger focus. Evidence disclosures work without hover.
- All observed route samples fit the document width at 390px. Representative widths retain one product header/footer and `--signal-action: #00eee4`.

## Review lenses

**Hierarchy and clarity.** The primary homepage action is clear. Spend submission needs earlier identity guidance and durable field-level feedback. The proof inspector needs a readable summary before raw data; lifecycle grouping currently concatenates labels. Legacy nested landmarks and multiple h1s weaken orientation on specific routes.

**Responsive engineering.** No document overflow was measured in this run. That does not establish complete evidence visibility: controls inside local scroll regions, real virtual keyboards, zoom and touch still need qualification. Local evidence wrappers should remain the scroll owners; no viewport lock or hidden evidence is proposed.

**Truth semantics.** Current canonical decisions and receipt stages remain authoritative. The audit does not reinterpret confidence, freshness, availability or a hash as permission or verified outcome. Recovery UI must distinguish missing records from service failure when the existing response allows that distinction, while keeping 403/404 private inspection generic.

**Performance.** The current research chunk is 1,562,518 raw bytes / 310,646 gzip bytes, with 406,690 raw bytes / 67,244 gzip bytes of research CSS. This is a demonstrated payload concern, not an observed INP failure. The lightweight homepage and tenant-aware Spend entry paths must stay independent of research imports.

**Accessibility.** Native labels, semantic actions, focus styling, status text and private key masking are present. Missing field-error associations and inconsistent hierarchy require correction and AT verification. Browser-native validation is a Premium contract violation; native validation and multiple h1s are not automatically WCAG failures. This run does not claim AA conformance.

## Standards and authority

- Existing `docs/design-system/constitution.md` owns appearance and truth vocabulary; `src/web/radarTokens.css` owns runtime tokens. Existing shell, status, async-state, lifecycle, evidence-row and table primitives are the canonical owners.
- [Apple accessibility guidance](https://developer.apple.com/design/human-interface-guidelines/accessibility) supplies the hierarchy/clarity lens; the installed Apple design reference also informed review. No Apple visual imitation is proposed.
- [WCAG 2.2](https://www.w3.org/TR/WCAG22/) governs the accessibility target. Relevant follow-up checks include error identification/instructions, focus order/visibility, reflow, target size, name/role/value and status announcements.
- [Google Web Vitals](https://web.dev/articles/vitals) distinguishes LCP, INP and CLS and uses field p75. Historical Lighthouse TBT is not an INP result.
