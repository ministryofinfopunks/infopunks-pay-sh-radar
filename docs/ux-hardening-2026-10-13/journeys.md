# User journeys and edge cases

Figr was attempted but is disconnected (`USER_NOT_LOGGED_IN`). This is an independent browser/source review, not a Figr-generated evaluation. Source-only observations are labeled and are not completed browser qualification.

| Journey | Observed behavior / evidence | Failure or misconception | Proposed correction and edge-case qualification |
|---|---|---|---|
| 1. First visit → Spend Check | Homepage advertises advisory checks; route ID deep-links correctly; empty key gets an authentication error. [Start](evidence/01-home-desktop.jpg), [form](evidence/02-spend-mobile-initial.jpg), [error](evidence/03-spend-key-error.jpg). | “No wallet required” can be understood as no operator identity required. Default `radar-browser` identity and machine-style intent need context. The corrective key field is not linked to the server error. | UX-01/05/12. Explain exploration vs authenticated submission in the existing form, link the existing integration documentation, validate fields before submit, preserve edits and focus the correction. Test no key, whitespace key, wrong key, wrong agent, expired identity and pasted credentials. Do not infer an agent from a key. |
| 2. Insufficient evidence | Actual local authenticated response: `insufficient_evidence`, 0 USDC, 0 accepted observations, no receipt or execution. [Result](evidence/04-insufficient-evidence.jpg). | The reason is truthful but general. “Inspect route evidence” drops the specific route. Missing Judgment stage means no issued record, not absence of an assessment. | UX-06/08. Preserve exact decision and free-assessment copy. Retain selected-subject navigation and show only returned reasons. Test unknown provider/endpoint identifiers, stale evidence, changed inputs and repeat submission. Do not generate proof to make the UI look complete. |
| 3. Policy-defined test spend | Source has the `test_spend_first` label and 402 quote handling. Current focused test proves quote-only/no automatic payment, but no fresh completed browser state was captured. | Users could read “Test spend first” as authorization to execute, or invent a test cap from the form budget. The canonical response does not expose a structured cap for the UI to derive. | Qualification HOLD (Q-01); apply existing decision/quote/no-execution language consistently. After approval, use a reviewed synthetic canonical response with explicit policy reasons. Display only policy details actually returned; unavailable cap/details remain unavailable. No “execute test” button or inferred allowance. |
| 4. Deterministic blocker denies spend | Source maps `do_not_spend` distinctly and renders server reasons. Legacy critical route lists blockers; its catalog evidence does not establish a canonical veto. No fresh canonical denial browser result was captured. | A critical catalog card or missing evidence could be mistaken for deterministic canonical denial. A retry could be understood as overriding the blocker. | Qualification HOLD (Q-01). Capture an actual canonical deterministic-veto fixture after approval, visibly retain the veto/reasons, provide evidence inspection and input correction, and show separate authorization boundaries. No override UI, reclassification or fabricated denial. |
| 5. Authorized / unauthorized receipt inspection | Owner loads pending Execution and Evaluation; changing to another tenant immediately removes private content; denied inspection stays generic. [Pending](evidence/06-pending-execution.jpg), [source](evidence/07-execution-source-open.jpg), [denied](evidence/08-receipt-denied.jpg), [Evaluation](evidence/09-evaluation.jpg). | Raw JSON is the only practical parent-navigation mechanism. “Missing evidence” after access denial may be mistaken for evidence nonexistence. Re-entering a long masked key is hard to correct. | UX-07/12/13. Add source-field summary, independently authenticated parent links and neutral “No authenticated record loaded” wording. Preserve generic private 403/404, clear-on-identity-change, no credential in URL/storage and separate verification. Test owner, other tenant, same tenant/wrong agent, invalid/expired/missing key, invalid receipt schema and verification outage. |
| 6. Pending execution / evaluation | Execution explicitly says pending; Evaluation says record exists / confirmed. Missing unrelated stages do not advance. [Execution](evidence/06-pending-execution.jpg), [Evaluation](evidence/09-evaluation.jpg). | Stage/status labels concatenate. A confirmed record can be mistaken for independently verified proof if users never inspect source. Pending state lacks a clear source timestamp/parent summary. | UX-06/07. Expose returned time/status/outcome fields and clarify verification scope. Keep manual read-only inspection; no invented polling result, auto-completion or inferred ancestry. Test pending→loaded change, unchanged pending, failed execution, disputed/uncertain evaluation and separate verification failure. Pending Evaluation fixture remains open. |
| 7. Backend outage and retry | Several research collections visibly return unavailable/degraded states or raw 404/codes. Current Spend client has 12s timeout and safe retry text in source. [Degraded](evidence/routes/004.jpg), [raw missing detail](evidence/routes/012.jpg), [projects unavailable](evidence/routes/111.jpg). | No local retry/return path on several surfaces. Missing object, unavailable service and empty collection are conflated. Current run did not stop/restart the shared API. | UX-04; Q-02 HOLD. Introduce bounded read-only recovery using existing hooks; preserve partial evidence and form values. After approval use isolated fault injection for 503, offline, slow response, malformed JSON, schema failure, abort and recovery. Prove same-attempt idempotency for identical Spend retries without changing the idempotency algorithm or issuing payments. |
| 8. Mobile navigation / evidence | Menu opens, Escape closes and focus returns to trigger. No document overflow in 138 samples at 390px or 84 representative seven-width checks. [Menu](evidence/12-mobile-navigation.jpg), [responsive matrix](evidence/responsive.json). | Lifecycle grouping, long raw source and semantic landmark duplication impede navigation. Width fit does not establish touch, zoom, keyboard or screen-reader usability. | UX-06/07/10. Keep all evidence, labeled local overflow and native disclosures. Qualify 200% zoom, 320px text reflow, keyboard source scrolling, menu arrows where applicable, VoiceOver/TalkBack and real iOS/Android virtual keyboards. No viewport scroll lock to force fit. |
| 9. Robinhood market exploration | Desk and market routes visibly preserve exact-contract scope, unavailable market totals and read-only/trading-unqualified copy. [Desk](evidence/routes/094.jpg), [market](evidence/routes/106.jpg), [Reflexive](evidence/routes/010.jpg). | Broken share dispatch and dead-end detail errors interrupt discovery→source→receipt. Project directory `not_found` lacks a meaningful recovery path. Narrative alias has duplicate h1s. | UX-03/04/10. Route existing readers correctly, retain unknown/stale/partial data and exact-contract distinction. Test valid contract, invalid address, untracked contract, source mismatch, stale and unavailable pairs, missing receipt, and share/permalink return flow. No buy/sell recommendation, trading authority or new market truth. |
