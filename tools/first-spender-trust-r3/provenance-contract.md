# Live-evidence contract v1 — review specification

**DRAFT / HOLD. This is a fail-closed candidate contract, not production authorization or a deployed fix.** The executable reference is `assurance.mjs`, with mandatory fields/constants in `live-evidence.contract.v1.json`. Every error, omission, null where a concrete declaration is required, malformed timestamp, unknown version or extra field quarantines the candidate for new decisions. No fallback to `catalog_source: live` exists in this reference. Production source remains unchanged pending independent assessment.

## Trust roots and independently authenticated identity

The verifying host receives a current registry and its exact SHA-256 pin from an independent authorized custodian outside the evidence bundle. Accepting a submitter's own registry/pin would defeat the boundary. Registry keys carry a role, organization, independent identity evidence digest, exact grant digest, validity interval and explicit revocation flag. No implicit wildcard, ambient admin token, HTTP field, source label or environment toggle selects a trusted identity. The registry itself and identity evidence must be independently examined and approved; a digest or distinct organization string is not proof of identity or independence. None has yet been supplied. Missing or stale registry/revocation snapshots quarantine new intake. Historical key verification and current admission are separate operations.

V1 deliberately supports one authentication profile: source-native Ed25519 signature plus collector signature and an independent provenance review. A provider that does not sign this profile is unsupported until reviewers approve a **different, versioned authenticated-capture profile** describing TLS identity, capture integrity, collector isolation, replay resistance and source authority. Never have a collector impersonate a source or sign invented provider authority. This constrained reference may be incompatible with actual source contracts; the data review must establish applicability before adoption. No real source profile is claimed to qualify today.

## Signed assertion and permitted use

Source and collector sign `UTF8("INFOPUNKS-R3/{role}/v1\n" + canonical(body))`, where `body` is the exact assertion without all three signature fields. Reviewer signs the same domain with role `provenance-reviewer` over `{body, source_signature, collector_signature}`. Signatures are 64-byte Ed25519 values in canonical base64. Keys are not supplied inside assertions. All signed values are JSON, recursively sorted object keys, ordered arrays, finite safe integers; no floating amounts, undefined values or non-JSON objects. This is a versioned repository-local encoding, not a claim of RFC 8785 compliance.

Each signer has an exact grant over `{scope, source_id, source_contract_hash, collection_method, permitted_use, max_age_ms}`. Scope includes tenant, authenticated principal, typed subject, network, exact recipient/route, intent, candidate and policy hashes. Host-supplied expected scope must come from authenticated request/policy context. Source, collector and reviewer must represent three independently verified organizations. Registry grants enforce what they may attest, rather than trusting an assertion's self-described authority. `collector_id` must equal the collector's registry key ID; independently reviewed identity evidence binds that key to the actual collector.

`authority: reviewed_live` means eligible **as evidence for a new judgment**, conditional on actual source-contract and data review. `spending_authority: none` is mandatory. The sole permitted use is `new_judgment_evidence`; training, publication, redistribution, inferred settlement, execution and treasury authorization are not implicitly licensed. A separate license/source-contract review must establish that use is allowed. Provider claims, catalog entries, unsigned labels, wallet payment, model confidence and a signed receipt alone cannot establish observed fact truth, delivery, value or settled funds. Independent reviewer must check source competence, authenticity, collection method, evidence limitations and disputes.

## Content, freshness and immutable binding

The detached assertion binds original `observation_id`, canonical receipt hash, raw artifact byte digest and source contract digest. The verifier requires actual receipt and artifact bytes, validates the observation/payload hashes and exact subject/intent/source/time bindings, requires sufficient evidence and references, and verifies the signed assertion. The receipt envelope remains canonical V1; its old provenance is never edited or rehashed. Authentication does not independently validate payload semantics: canonical fact schemas, domain adapters, candidate/policy hashes, source competence and all judgment gates still apply in a future reader. A reference success therefore says only `CANDIDATE_EVIDENCE_ONLY`, never ALLOW/proceed.

Observed, ingested, registry, key and expiry times are explicit UTC instants. Future observation/ingestion, expiry at now, absent TTL, age at the limit and TTL greater than host policy fail closed. Policy max age is independently configured, never raised by evidence. Revocation and new disputes/supersession must be rechecked at issuance and every existing authorization boundary. A verified old observation is not fresh current evidence. Source sequence/replay caches and newest-adverse-observation checks remain necessary in a future reader; the stateless reference does not replace them.

## Required production split, not installed here

Introduce separately versioned **new-issuance admission** and **historical replay**. Freeze V1/V2 replay on original inputs and original policy; do not replace its shared predicate in place. New paid quote admission, new signed judgment issuance, economic-candidate filtering, cached quote reuse and capability issuance must reject/quarantine missing or ambiguous provenance under a new explicit admission version, bound into the new frozen decision context. Recheck trust/expiry/revocation before paid acceptance so a quote cannot outlive evidence authority. Previously paid or historical receipts do not grandfather new authority. Existing signed capabilities, reservation/idempotency, tenant isolation, settlement and recovery guards remain mandatory.

Unknown/ambiguous intake must produce a non-authorizing `insufficient_evidence` outcome before requesting a paid judgment; record the quarantine reason in an append-only sidecar. Preserve historical bytes and independently authenticated historical verification. Reobservation/reattestation creates a new linked record; neither an ALTER/UPDATE nor an assumed authority backfill is acceptable. If compatibility cannot be proved, stop new issuance and retain read-only historical verification. Independently review actual contracts and history using the inventory before proposing this reader change.
