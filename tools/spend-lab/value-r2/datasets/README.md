# Dataset separation and freeze

Development is the original 20-task PR #16 benchmark. Its source and negative result remain unchanged. Holdout contains 96 new cases across eight new contract families and twelve provider/evidence conditions; no original task input or provider implementation is reused. It is a deliberately balanced local stress set, not a market sample. Synthetic outputs and duration bins are explicit; expected outputs are separately authored answer keys. The curator script imports no Radar, policy or development module. It generates offers, observed synthetic artifacts and correctness/net-value labels before any R2 policy evaluator exists.

The first R2 commit freezes the entire holdout plus its canonical-content commitments before strategy evaluation. Later source verification compares those files to that Git commit. Policy code receives only offers, never labels, outputs, should-spend labels or loss outcomes. Scoring joins outcomes only after all decisions are frozen. Development and holdout are reported separately, never pooled for a winning headline. Holdout evaluation is one-shot for the preregistered policy/configuration; sensitivity sweeps are descriptive evaluations, not additional untouched holdouts. Any later tuning needs a new holdout/version.

The human authorized a separate local curation track. This is same-operator synthetic curation, not an external independent dataset, secret holdout, independently administered credential boundary or externally verified market valuation. The source-reading operator can anticipate fixtures. Real economic usefulness remains NOT ESTABLISHED. External curator, observed provider evidence and independent economic valuation are still required.
